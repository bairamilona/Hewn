# Hewn — пошаговая инструкция по публикации в App Store и Google Play

Сейчас Hewn — это веб-приложение (PWA: `index.html` + `manifest.json` + `sw.js`), без нативного iOS/Android проекта. Чтобы попасть в сторы, его нужно «обернуть» в нативную оболочку. Ниже — полный путь от обёртки до публикации, шаги разбиты на маленькие действия.

Рекомендуемый инструмент обёртки — **Capacitor** (от Ionic): берёт твой существующий веб-код, генерирует нативные Xcode- и Android Studio-проекты, не требует переписывания приложения.

---

## ЧАСТЬ 0. Подготовка деплоя

1. Убедись, что прод-версия доступна по HTTPS — она уже есть: `https://hewn-mauve.vercel.app`.
2. Проверь, что `manifest.json`, иконки (`assets/icons/icon-192.png`, `icon-512.png`) и `sw.js` отдаются с продакшен-домена (открой в браузере и убедись, что 200 OK).
3. Зафиксируй финальный URL — он понадобится при настройке обёртки.

## ЧАСТЬ 1. Оборачиваем PWA в нативное приложение через Capacitor

### 1.1. Установка Capacitor в проект
1. В терминале перейди в папку проекта: `cd /home/user/Hewn` (или твой локальный путь).
2. Установи зависимости: `npm install @capacitor/core @capacitor/cli @capacitor/ios @capacitor/android`.
3. Инициализируй Capacitor: `npx cap init Hewn com.hewn.app --web-dir .`
   - `Hewn` — отображаемое имя приложения.
   - `com.hewn.app` — Bundle ID / Application ID (можно заменить на свой, например `com.bairamilona.hewn`; главное — использовать его одинаково и в Xcode, и в Android Studio, и в обеих консолях).
   - `--web-dir .` — указывает, что веб-код лежит в корне репозитория (там, где `index.html`).

### 1.2. Настройка `capacitor.config.json`
1. Открой созданный файл `capacitor.config.json`.
2. Если хочешь, чтобы приложение грузило прод-сайт напрямую (а не локальную копию HTML), добавь блок `server`:
   ```json
   "server": { "url": "https://hewn-mauve.vercel.app", "cleartext": false }
   ```
   Это самый простой вариант — обновления сайта сразу видны в приложении без пересборки.
3. Сохрани файл.

### 1.3. Добавление платформ
1. Добавь iOS-проект: `npx cap add ios`.
2. Добавь Android-проект: `npx cap add android`.
3. Команда создаст папки `ios/` и `android/` с полноценными нативными проектами.
4. Синхронизируй веб-код в нативные проекты: `npx cap sync`.

### 1.4. Иконки и splash screen
1. Установи генератор ассетов: `npm install -D @capacitor/assets`.
2. Подготовь два исходника в папке `assets/`:
   - `icon-source.png` — квадратная иконка минимум 1024×1024 (можно взять `assets/icon-1024.png`, который уже сгенерирован в нужном dithered-стиле).
   - `splash-source.png` — картинка для экрана загрузки 2732×2732 (можно сделать на основе того же дизайна на фоне `#F7F6F3`).
3. Запусти генерацию: `npx capacitor-assets generate --iconBackgroundColor '#F7F6F3' --splashBackgroundColor '#F7F6F3'`.
4. Команда сама разложит иконки нужных размеров по `ios/` и `android/` проектам.

## ЧАСТЬ 2. iOS — публикация в App Store

### 2.1. Apple Developer аккаунт
1. Зайди на developer.apple.com и зарегистрируйся в Apple Developer Program (если ещё нет) — стоит $99/год.
2. Подтверди личность/организацию (может занять 24–48 часов).

### 2.2. Открываем проект в Xcode
1. Открой `ios/App/App.xcworkspace` (именно `.xcworkspace`, не `.xcodeproj`) в Xcode.
2. Подожди, пока Xcode проиндексирует проект и подтянет зависимости через CocoaPods.

### 2.3. Настройка подписи (Signing)
1. В Xcode выбери проект `App` в навигаторе слева → таргет `App` → вкладка **Signing & Capabilities**.
2. Включи **Automatically manage signing**.
3. В поле **Team** выбери свою команду (привязанную к Apple Developer аккаунту).
4. Проверь **Bundle Identifier** — он должен совпадать с тем, что ты указал в `cap init` (например `com.hewn.app`).
5. Xcode автоматически создаст provisioning profile и сертификат.

### 2.4. Базовые настройки приложения
1. На вкладке **General** укажи **Display Name**: `Hewn`.
2. Проверь **Version** (например `1.0.0`) и **Build** (например `1`).
3. На вкладке **Info** убедись, что ориентация выставлена только Portrait (соответствует `manifest.json`).

### 2.5. Тестовый запуск
1. Выбери симулятор (например iPhone 15 Pro) в верхней панели Xcode.
2. Нажми ▶️ Run и убедись, что приложение открывается и показывает Hewn.
3. Проверь основные сценарии: добавление протеина, добавление активности, открытие Shelf.

### 2.6. Создание записи приложения в App Store Connect
1. Зайди на appstoreconnect.apple.com → **My Apps** → **+** → **New App**.
2. Заполни:
   - **Platform**: iOS
   - **Name**: `Hewn` (см. `app-store-copy.md`)
   - **Primary language**: English (или Russian, на твой выбор)
   - **Bundle ID**: выбери тот же, что в Xcode (`com.hewn.app`)
   - **SKU**: любой уникальный идентификатор, например `hewn-001`
3. Нажми **Create**.

### 2.7. Заполнение карточки приложения
Используй готовый текст из `app-store-copy.md` — копируй построчно:
1. **Subtitle** (max 30 символов) → `Protein + movement, simply`
2. **Promotional text** → текст из файла
3. **Description** → полный текст описания из файла
4. **Keywords** → строка из секции Keywords
5. **Support URL** и **Marketing URL** → ссылки из файла
6. **Category** → Health & Fitness, **Secondary** → Lifestyle
7. Загрузи скриншоты из папки `screenshots/` (уже сделаны под iPhone 14 Pro Max, 1290×2796).
8. Загрузи иконку приложения 1024×1024 (`assets/icon-1024.png`) в раздел App Information.

### 2.8. Архивация и загрузка билда
1. В Xcode выбери в верхней панели **Any iOS Device (arm64)** вместо симулятора.
2. Меню **Product → Archive**, дождись завершения сборки.
3. В открывшемся окне Organizer нажми **Distribute App**.
4. Выбери **App Store Connect → Upload**, далее везде жми **Next** с настройками по умолчанию (Automatically manage signing).
5. Дождись завершения загрузки (несколько минут) — Xcode пришлёт уведомление об успехе.
6. В App Store Connect зайди в **TestFlight** или сразу в карточку приложения — билд появится через 10–30 минут после обработки.

### 2.9. Прикрепление билда и отправка на ревью
1. Вернись в карточку приложения → раздел **Build** → выбери загруженный билд.
2. Заполни **Age Rating** (4+, см. `app-store-copy.md`).
3. Заполни раздел **App Privacy** — укажи, что приложение НЕ собирает данные (всё хранится локально на устройстве).
4. Нажми **Save**, затем **Add for Review** → **Submit for Review**.
5. Жди решения Apple (обычно 24–48 часов).

## ЧАСТЬ 3. Android — публикация в Google Play

### 3.1. Google Play Console аккаунт
1. Зайди на play.google.com/console и зарегистрируйся как разработчик — разовый взнос $25.
2. Заполни данные аккаунта разработчика (имя, контакты, адрес).

### 3.2. Открываем проект в Android Studio
1. Открой папку `android/` (созданную Capacitor) в Android Studio как проект.
2. Дождись, пока Gradle синхронизируется (может занять несколько минут при первом запуске).

### 3.3. Настройка приложения
1. Открой `android/app/build.gradle`.
2. Проверь `applicationId` — должен совпадать с тем, что указывал при `cap init` (например `com.hewn.app`).
3. Проверь `versionCode` (целое число, например `1`) и `versionName` (например `"1.0.0"`).

### 3.4. Тестовый запуск
1. Запусти эмулятор (Pixel 7, Android 14) через **Device Manager** в Android Studio.
2. Нажми ▶️ Run и убедись, что приложение открывается и работает корректно.

### 3.5. Создание ключа подписи (keystore)
1. В Android Studio: **Build → Generate Signed Bundle / APK**.
2. Выбери **Android App Bundle**, нажми **Next**.
3. Нажми **Create new...** для создания нового keystore:
   - укажи путь для сохранения файла `.jks` (сохрани его в надёжном месте — он понадобится для ВСЕХ будущих обновлений приложения!)
   - придумай и сохрани пароль keystore и пароль ключа (alias)
   - заполни данные сертификата (имя, организация, страна)
4. **ВАЖНО**: сделай резервную копию `.jks` файла и паролей — без них нельзя будет выпускать обновления приложения.

### 3.6. Сборка подписанного App Bundle (AAB)
1. После создания/выбора keystore нажми **Next**.
2. Выбери **release** вариант сборки.
3. Нажми **Finish** и дождись завершения сборки.
4. Готовый файл `.aab` появится в `android/app/release/`.

### 3.7. Создание приложения в Play Console
1. В Play Console нажми **Create app**.
2. Заполни:
   - **App name**: `Hewn — Protein & Movement` (см. `play-store-copy.md`)
   - **Default language**: English (US) или Russian
   - **App or game**: App
   - **Free or paid**: Free
3. Прими декларации (контент-политика, экспортные законы США) и нажми **Create app**.

### 3.8. Заполнение Store listing
Используй готовый текст из `play-store-copy.md`:
1. **Short description** (max 80 симв.) → текст из файла
2. **Full description** (max 4000 симв.) → текст из файла
3. **App icon** (512×512) → загрузи `assets/play-icon-512.png`
4. **Feature graphic** (1024×500) → загрузи `assets/play-feature-1024x500.png`
5. **Phone screenshots** → загрузи 2–8 файлов из `screenshots-android/`
6. **Category** → Health & Fitness, теги — см. `play-store-copy.md`
7. **Contact details** → email и сайт из файла

### 3.9. Заполнение обязательных разделов перед релизом
Play Console не даст опубликовать приложение, пока не заполнены:
1. **Privacy Policy** → вставь ссылку `https://hewn-mauve.vercel.app/privacy.html`
2. **App access** → укажи, что приложение не требует логина (доступны все функции без входа)
3. **Ads** → укажи, что в приложении нет рекламы
4. **Content rating** → пройди опросник (выбери категорию Health/Lifestyle, ответь "нет" на вопросы про насилие/контент для взрослых) — получишь рейтинг "Everyone"/"Для всех"
5. **Target audience** → укажи возрастную группу (например 18+ или "не предназначено специально для детей")
6. **Data safety** → заполни форму: "Данные не собираются", "Данные не передаются третьим лицам", "Все данные хранятся локально на устройстве"
7. **Government apps / News apps** → отметь "Нет" (не относится к Hewn)

### 3.10. Создание релиза и загрузка AAB
1. Слева в меню выбери **Production** (или начни с **Internal testing**, если хочешь сначала протестировать на реальных устройствах).
2. Нажми **Create new release**.
3. Загрузи файл `.aab`, собранный на шаге 3.6.
4. Заполни **Release name** (например `1.0.0`) и **Release notes** (например: "Первый релиз Hewn").
5. Нажми **Save**, затем **Review release**.

### 3.11. Отправка на проверку
1. Проверь, что все разделы из 3.9 отмечены зелёной галочкой (без них релиз не пройдёт проверку).
2. Нажми **Start rollout to Production** (или **Internal testing**, если решил тестировать сначала).
3. Подтверди отправку.
4. Жди решения Google (обычно от нескольких часов до нескольких дней для нового аккаунта разработчика).
